# Stage 0 — 앵커 입력 기준 (제안·미승인)

상태: **제안·미승인**. 이 문서의 기준값은 Bell 이 승인한 값이 아니다. 코드의 판정 기준은 바꾸지 않았다.
근거: 이슈 #16. 기준 커밋: main `522bef3`.
재현: `python -m experiments.stage0.anchor_criteria` (합성 벡터). 아래 표 1~3 이 이 출력과 같은지는 `tests/stage0/test_anchor_criteria.py` 가 확인한다.

이 문서의 수치는 전부 **합성 벡터**에서 나왔다. 실제 임베딩 모델의 측정이 아니다.

## 1. 문제

앵커 투영 $P_A$ 는 앵커들이 만드는 부분공간 전체를 신뢰한다. 방향마다 "얼마나 믿을지"를 다르게 두지 않는다. 그래서 앵커 하나가 다른 앵커와 아주 조금만 달라도, 그 작은 차이가 가리키는 방향이 통째로 앵커 부분공간에 들어간다.

main `522bef3` 에서 실행으로 재현한 두 사례:

| 사례 | 입력 | 결과 |
|---|---|---|
| 거의 겹치는 앵커 | 앵커 `[1,0,0]`, `[1,1e-6,0]`, 상태 `diag(0,1,0)` (유출 방향) | 허용됨. 앵커 겹침 1.0, $E=0$ 일 때 $Q=1.0$ |
| 전체 공간을 채우는 앵커 | 3차원에 앵커 3개 (`np.eye(3)`), 같은 상태 | 허용됨. $P_A=I$ 라서 어떤 상태든 겹침 1.0, $Q=1.0$ |

두 사례 모두 `tests/stage0/test_input_contract.py` 에 `xfail(strict=True)` 로 남겼다. 기준이 정해져 코드를 고치면 XPASS 로 실패하므로 그때 표시를 제거한다.

이번에 결정 없이 고친 것은 이 문서의 대상이 아니다: 앵커 수가 차원을 넘는 경우(반드시 선형종속) 거부, 복소·비유한·영벡터·빈 앵커 거부.

## 2. 두 가지를 구분한다

**(가) 수치적 선형종속.** 사실상 같은 벡터가 부동소수점이나 재계산 잡음만큼만 다른 경우다. 판정량은 단위 정규화한 앵커 행렬의 특이값 비 $\sigma_{min}/\sigma_{max}$ 다. 앵커가 둘이면 $\tan(\theta/2)$, $\theta$ 는 두 앵커 사이의 각이다. 이 경우의 문제는 새로 들어오는 방향을 잡음이 정한다는 것이다. 같은 문장을 다시 임베딩하면 $P_A$ 가 달라진다 (표 2).

**(나) 문장 의미 유사도.** 서로 다른 문장인데 코사인이 높은 경우다 (예: 0.93~0.99). 수치적으로는 안정하다 (표 2). 여기서의 질문은 "두 문장의 차이가 가리키는 방향을 앵커로 믿을 것인가"이고, 계산의 문제가 아니라 앵커 설계의 문제다.

읽는 법:

- 현재 규칙은 보고된 사례(차이 1e-6)를 허용한다.

- 쌍별 코사인 기준은 뜻이 가까운 서로 다른 문장쌍(0.93, 0.97)을 거부한다. 그리고 "앵커 3개, 셋째 = 앞 둘의 조합" 사례를 놓친다. 가장 가까운 쌍의 코사인이 0.81 인데 셋이 거의 한 평면에 있다.
- 두 계열은 서로 다른 문제를 잡는다. 수치적 겹침을 빠짐없이 잡는 것은 특이값 비 쪽이다.

## 4. 표 2 — 재계산 잡음에 대한 민감도

마지막 앵커가 앵커 부분공간에 새로 들이는 방향의 크기를 $s$ 라 하자 (앞 앵커들의 성분을 뺀 나머지의 크기). 그 앵커가 크기 $\delta$ 의 잡음으로 흔들리면, 새 방향 중 잡음 방향으로 바뀌는 비율은 최악의 경우

$$
\frac{\delta^2}{s^2+\delta^2}
$$

이다. 0 이면 다시 임베딩해도 $P_A$ 가 같고, 1 이면 새 방향을 잡음이 정한다. 테스트가 이 공식을 투영 행렬로 직접 계산한 값과 비교한다.

| 사례 | 새 방향의 크기 s | 잡음 1e-7 | 잡음 1e-5 |
|---|---|---|---|
| 정확히 같은 앵커 | 0 | 1 | 1 |
| 차이 1e-9 | 1e-09 | 1 | 1 |
| 차이 1e-6 (보고된 사례) | 1e-06 | 0.0099 | 0.99 |
| 차이 1e-3 | 0.001 | 1e-08 | 0.0001 |
| 코사인 0.999 | 0.045 | 5e-12 | 5e-08 |
| 코사인 0.99 | 0.14 | 5e-13 | 5e-09 |
| 코사인 0.97 | 0.24 | 1.7e-13 | 1.7e-09 |
| 코사인 0.93 | 0.37 | 7.4e-14 | 7.4e-10 |
| 코사인 0.8 | 0.6 | 2.8e-14 | 2.8e-10 |
| 코사인 0.5 | 0.87 | 1.3e-14 | 1.3e-10 |
| 직교 | 1 | 1e-14 | 1e-10 |
| 앵커 3개, 셋째 = 앞 둘의 조합 + 1e-6 | 1e-06 | 0.0099 | 0.99 |
| 앵커 3개, 쌍별 코사인 모두 0.3 | 0.93 | 1.2e-14 | 1.2e-10 |

읽는 법:

- 잡음 1e-7 은 float32 반올림 수준이다. 이때 보고된 사례는 새 방향의 약 1% 가 잡음이고, 차이 1e-9 는 전부 잡음이다.
- 서로 다른 문장에 해당하는 줄(코사인 0.999 이하)은 잡음이 100배 커져도 5e-08 이하다. 뜻이 가까운 문장쌍은 수치적으로 문제가 없다.
- $s$ 가 잡음의 100배 이상이면 비율은 1e-4 이하다. 수치 기준의 τ 는 실제 재계산 잡음보다 충분히 커야 한다는 뜻이다.
- **확인 필요**: 실험 1 파이프라인의 실제 재계산 잡음 크기는 측정하지 않았다. 같은 문장을 같은 환경·다른 환경에서 두 번 임베딩한 차이를 재야 한다.

## 5. 표 3 — 현재 규칙의 척도 의존성

현재 규칙은 정규화하지 않은 앵커에 절대 임계값 1e-9 를 쓴다. 그래서 같은 방향이라도 벡터의 크기에 따라 판정이 달라진다.

| 입력 | 현재 판정 |
|---|---|
| 단위 크기, 차이 1e-12 | 거부 |
| 같은 두 방향을 1e6 배 | 허용 |
| 앵커 1개, 크기 1 | 허용 |
| 앵커 1개, 크기 1e-10 | 거부 |

실험 1 의 임베딩은 단위 벡터라 지금 결과에는 영향이 없다. 기준을 바꿀 때 "정규화한 뒤 판정"으로 함께 고치는 것을 제안한다.

## 6. 방향 하나가 더 들어오면 실제로 얼마나 달라지나

무작위 단위 벡터와 $m$ 차원 부분공간의 평균 겹침은 정확히 $m/d$ 다. 384차원에서 m=1이면 0.0026, m=2이면 0.0052, m=3이면 0.0078, m=4이면 0.0104 이다. 잡음 방향 하나가 앵커 부분공간에 더 들어와도, 무작위 상태의 겹침은 평균 0.0026 늘어난다.

보고된 사례에서 겹침이 1.0 이 된 것은 새 방향이 유출 방향과 정확히 일치하도록 만든 최악의 경우다. 실험 1 설계 §5.3(제안)대로 앵커를 신뢰된 입력(정책 상수, 사용자 프롬프트, 스위트 이름)만으로 만든다면 공격자가 이 방향을 고를 수 없다. 이 격리는 아직 구현되지 않았다.

따라서 이 문제의 무게는 "공격이 통과한다"가 아니라 다음 두 가지다. 같은 입력에서 게이트 입력이 재현되지 않을 수 있다. 그리고 의도하지 않은 방향이 신뢰 대상에 들어가도 오류가 나지 않는다.

## 7. 실험 1 의 앵커 3종과의 관계

실험 1 설계 §5 의 앵커는 작업마다 세 문장이다: a1 사용자 프롬프트(작업별), a2 정책 문장(공통), a3 스위트 범위 문장(스위트별).

- $m=3$ 이고 임베딩 차원은 384 라서 "전체 공간을 채우는 앵커"는 생기지 않는다.
- 97개 작업에서 세 문장이 글자 그대로 같은 경우는 없다 (`real_anchor_sets()` 로 확인, agentdojo 0.1.35, v1.2.2). 따라서 수치적 겹침은 지금 설계에서 자연히 생기지 않는다. 생긴다면 앵커를 만드는 코드의 버그(같은 문장을 두 번 넣음)일 가능성이 높고, 그때 오류로 드러나게 하는 것이 수치 기준의 역할이다.
- 의미 유사도는 다르다. 사용자 프롬프트가 스위트 범위 문장과 비슷한 작업이 있을 수 있다. **실제 코사인 분포는 측정하지 못했다.** 이 작업 환경에서는 임베딩 모델을 내려받을 수 없었다. `python -m experiments.stage0.anchor_criteria --real` 이 97개 작업에 대해 가장 가까운 쌍의 코사인과 특이값 비 분포, 후보 기준별 거부 건수를 출력한다 (`sentence-transformers`, `agentdojo==0.1.35` 필요). 이 경로는 가짜 임베딩으로 집계 부분만 테스트했고, 실제 모델을 불러오는 한 줄은 실행해 보지 못했다.
- 실험 1 의 앵커 민감도 분석(a1 단독 / a1+a2 / a1+a2+a3)에서 앵커를 더할수록 $m/d$ 만큼 기본 겹침이 늘어난다는 점도 함께 봐야 한다.

## 8. 제안 (미승인)

| # | 제안 | 근거 | 영향 |
|---|---|---|---|
| P1 | 수치 기준을 넣는다. 앵커를 단위 정규화한 뒤 $\sigma_{min}/\sigma_{max} < \tau$ 이면 거부. 제안값 $\tau = 10^{-4}$, 단 실제 재계산 잡음을 잰 뒤 그 100배 이상으로 맞춘다 | 표 1: 1e-6~1e-2 어디서나 서로 다른 앵커는 거부되지 않는다. τ = 1e-4 로 허용되는 두 앵커는 $s$ 가 약 2e-4 이상이라, 잡음이 1e-6 이어도 새 방향의 잡음 비율은 표 2 의 공식으로 약 2.5e-5 다 | 보고된 사례의 xfail 해제. 실험 1 의 정상 앵커에는 영향이 없을 것으로 예상하나 `--real` 로 확인 필요 |
| P2 | 쌍별 코사인 상한(의미 기준)은 지금 넣지 않는다. `--real` 실측 뒤에 정한다 | 수치적으로 안정하다. 정상 작업의 앵커 묶음을 거부할 수 있고 그 비율을 아직 모른다. 고차 겹침은 놓친다 | 없음 (현 상태 유지) |
| P3 | 앵커가 전체 공간을 채우면($m = d$) 거부한다 | $P_A = I$ 이면 Q 의 정렬 항이 아무 정보도 주지 않는다 | xfail 해제. 기존 `test_anchor_overlap_bounds` 의 `np.eye(5)` 줄을 고쳐야 한다. 실험 1($m=3$, $d=384$)에는 영향 없음 |
| P4 | 판정을 정규화 후에 한다 | 표 3 | 단위 벡터 입력에는 영향 없음 |

검토했지만 제안하지 않는 대안: 방향마다 특이값으로 가중하는 "가중 투영". 거부 대신 작은 방향을 약하게 믿는 방식이다. 그러면 $P_A$ 가 투영이 아니게 되어 D2(앵커 투영 탈위상)와 Q 의 정의가 달라진다. 정의를 바꾸는 연구 결정이므로 이 제안의 범위 밖이다.

## 9. Bell 이 정할 것

1. **거의 같은 앵커를 걸러내는 수치 기준을 넣을지, 값은 얼마로 할지.** 왜: 지금은 사실상 같은 문장이 두 번 들어가도 오류가 나지 않고, 그 미세한 차이가 "허용 방향"으로 들어간다. 선택지: 넣지 않음 / 1e-6 / 1e-4(제안) / 1e-2. 어느 값을 골라도 서로 다른 문장은 거부되지 않는다.
2. **뜻이 비슷한 문장도 거부할지.** 왜: 비슷한 두 문장의 차이 방향을 믿을지의 문제다. 제안은 실측 뒤 결정이다. 실측 전에는 정상 작업이 몇 건 거부될지 모른다.
3. **앵커가 전체 공간을 채우면 거부할지.** 왜: 그 경우 Q 게이트가 아무것도 걸러내지 못한다. 제안은 거부다. 실험 1 에는 영향이 없다.

## 10. 하지 않은 것
